# МояКарта24 — лендинг

Единая платформа оформления региональных карт России. Пилот — транспортная карта
АЛГА в Республике Башкортостан.

Это **информационный лендинг**: маркетинговые страницы и справка по карте.
Оформление, личный кабинет, оплата и трекинг переезжают в веб-приложение —
здесь их нет, заказы на этапе пилота ведутся вручную по агентскому договору.

## Стек

Vite · React 19 · React Router · TypeScript · Tailwind CSS v4.

Все страницы предрендерятся статически — это принципиально: продвижение строится
на региональных страницах, а Яндекс плохо индексирует клиентский рендер. Готовый
HTML лежит в `dist/`, браузер его гидратирует, дальше навигация идёт клиентская.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # прод-сборка + пререндер в dist/
npm run preview      # посмотреть собранное, как на боевом хостинге
npm run lint         # eslint
npm run typecheck    # tsc --noEmit
```

## Как устроена сборка

`npm run build` делает три шага:

1. `vite build` — клиентский бандл и шаблон `dist/index.html`;
2. `vite build --ssr src/entry-server.tsx` — та же аппа для рендера в строку (`.ssg/`);
3. [`scripts/prerender.mjs`](scripts/prerender.mjs) — прогоняет её по всем адресам
   и раскладывает результат: `dist/<путь>/index.html`, плюс `404.html`,
   `sitemap.xml` и `robots.txt`.

Список адресов и метатеги собраны в [`src/lib/pages.ts`](src/lib/pages.ts) — это
единственный источник правды и для пререндера, и для sitemap, и для подстановки
`<head>` при клиентской навигации. Сама страница объявляет свои теги рядом с
компонентом: `export const head` (замена `export const metadata` из Next).

Хостинг нужен любой статический. Единственное требование — отдавать
`/<путь>/index.html` по адресу `/<путь>` (nginx `try_files $uri $uri/index.html`;
Netlify, Cloudflare Pages и GitHub Pages делают это сами).

## Ветки и деплой

| Ветка | Что делает |
| --- | --- |
| `develop` | Рабочая. На пуш и в PR гоняется CI: `typecheck`, `lint`, полная сборка |
| `production` | Боевая. Пуш публикует сайт на GitHub Pages |

Публикует [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml): собирает
`dist/` и отдаёт его в Pages. Выкатить прод — влить `develop` в `production`:

```bash
git switch production && git merge --ff-only develop && git push
```

Домен — `mycard24.ru`, лежит в [`public/CNAME`](public/CNAME) и попадает в `dist`
при каждой сборке. Файл обязателен: без него Pages сбрасывает привязку домена.
Тот же адрес прописан в `site.url` — от него считаются canonical, sitemap и JSON-LD.

Один раз в настройках репозитория нужно выбрать **Settings → Pages → Source:
GitHub Actions**, а у домена — направить DNS на Pages (A-записи на
`185.199.108–111.153` для `mycard24.ru` и `CNAME` на `<owner>.github.io` для
`www`). Базовый путь сайта — корень, поэтому `base` в `vite.config.ts` не нужен;
он понадобился бы только при публикации в подкаталог вида `/repo/`.

## Структура URL

Служебные разделы — по-английски, названия субъектов — латиницей как имена собственные.

| URL | Что это |
| --- | --- |
| `/` | Главная: выбор региона |
| `/regions` | Все регионы |
| `/bashkortostan` | Страница региона |
| `/bashkortostan/transport` | Страница карты: цена, польза, география, FAQ |
| `/delivery`, `/faq`, `/contacts` | Информационные |
| `/privacy`, `/offer` | Юридические (заглушки, `noindex`) |

## Как добавить регион

Одна запись в [`src/content/regions.ts`](src/content/regions.ts) — код трогать не нужно.
Страницы, карта в герое, sitemap и футер подхватят её сами.

```ts
{
  slug: 'orenburg',                  // → /orenburg, если статус 'available'
  name: 'Оренбургская область',
  shortName: 'Оренбургская область',
  locative: 'в Оренбургской области',
  status: 'soon',                    // 'available' — когда запустились
  summary: 'Готовим запуск',
  // landmark необязателен: у «скоро» карточка нейтральная, без снимка
  map: {
    subjectId: 'Orenburg',           // имя субъекта в Natural Earth
    capital: 'orenburg',             // ключ из src/content/cities.ts
    // flag: { src: '/regions/flags/56.svg', aspect: 3 / 2 },
  },
  faq: [ /* вопросы про транспортную систему региона */ ],
  cards: [ /* продукты региона */ ],
}
```

Геометрия в контенте не хранится: контур, центр и габариты субъекта берутся по
`subjectId` из сгенерированного `src/components/hero/russia-map-data.ts`.
Список `subjectId` — там же, в `SUBJECTS`.

Страницы получают только запущенные регионы (`status: 'available'`). У «скоро»
нет ни страницы, ни ссылки, ни строки в sitemap — они видны лишь в списке
регионов и на карте в герое.

## Карта России в герое

Границы всех 85 субъектов — реальные, из Natural Earth 50m. Пересобрать:

```bash
npm run build:map    # качает geojson, проецирует, упрощает, пишет russia-map-data.ts
```

Результат коммитится, поэтому обычная сборка офлайновая. Контуры упрощаются тем
сильнее, чем дальше субъект от регионов платформы: камера героя ходит только
вокруг них, а изрезанное побережье Чукотки весит больше всей остальной карты.
Добавили регион или город в `src/content/cities.ts` — перегенерируйте.

## Ассеты

| Файл | Статус |
| --- | --- |
| `public/products/transport_alga.jpg` | Официальный рендер карты АЛГА |
| `public/regions/bashkortostan-{640,1280}.webp` + `-1280.jpg` | Фото Уфы (мечеть «Ляля-Тюльпан»): webp для `srcSet`, jpg — фолбэк |
| `public/regions/bashkortostan{,2,3,4}.png/.jpg/.svg` | Исходники и черновики, **в вёрстке не используются**. Лежат в `public/`, поэтому попадают в сборку — перенесите их за пределы `public/` или удалите |
| `public/regions/flags/02.svg` | Флаг Башкортостана — подложка выделенного региона на карте героя |
| `public/operators/brsc.svg` | Знак АО «БРСК» для блока оператора |
| `public/regions/{tatarstan,omsk,moscow}.svg` | Не используются: у регионов «скоро» карточка нейтральная |
| `public/icon.svg` | Фавикон — знак из `docs/prototypes/logo.svg` |

Готовых вариантов изображения нет «на лету», как это делал `next/image`: размеры
готовятся заранее и перечисляются в `landmark.srcSet`. Сгенерировать их можно
так:

```bash
npx sharp-cli -i original.png -o public/regions -f webp -q 78 resize 1280
npx sharp-cli -i original.png -o public/regions -f webp -q 78 resize 640
```
